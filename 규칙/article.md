# 상세페이지 규칙 (Claude Code가 읽는다)

- **학생은 이 파일을 고치지 않는다.** 학생은 `콘텐츠/폴더/`에 원본 사진 · 영상 · 음악을 넣고 `글.md`를 쓴다
- Claude Code는 상세페이지를 만들 때 이 규칙, `규칙/공통틀.md`, `규칙/사진정리.md`, `콘텐츠/우리웹진.md`(웹진 이름 · 메뉴 · CTA · 글쓴이), 그 폴더의 `글.md` · `사진/` · `영상/` · `뮤직/`을 읽는다
- 파일: `public/articles/기사이름.html`
- 테스트 주소: 우리 팀 Cloudflare 작업 주소 `/articles/기사이름.html`
- 실제 주소: `lxwebzine.hankyung.com/teamN/articles/기사이름.html` (한경닷컴이 검수 후 서버에 올린다)
- 역할: 기사 한 편을 읽는 페이지. 광고로 서브메인에 들어온 사람이 "더 읽는" 곳이고, 공유 링크로 바로 들어오는 사람도 있다.
- 기준: 한경트래블의 화면 레이아웃과 색감. (실측)은 한경트래블에서 측정한 값, (제안)은 새로 정한 값이다.
- 샘플: 강사가 보여 주는 샘플 웹진 (팀 저장소에는 들어 있지 않다. 이 규칙만 따른다)
- 공통 스타일·스크립트: 서브메인과 같은 `../css/style.css`, `../js/site.js`를 쓴다. 색·글자·간격을 페이지마다 다시 적지 않는다

## 0. 유형 고르기

기사마다 6가지 중 하나를 고른다. 학생은 `글.md`의 `## 유형` 칸에 한글 이름(블로그형 등)을 쓴다. `type`은 같은 유형을 가리키는 영문 이름이다.

| 유형 | type | 모양 | 어울리는 기사 | 필요한 사진 | 난이도 |
|---|---|---|---|---|---|
| A. 블로그형 | `blog` | 제목 → 본문 → 사진이 차례로 이어짐 | 정보가 많은 기사, 후기 | 가로 16:9 몇 장 | 쉬움 |
| B. 매거진 커버형 | `magazine` | 큰 표지 사진이 첫 화면을 덮고, 중간에 큰 인용문과 화면 끝까지 닿는 사진 | 분위기가 중요한 대표 기사 | 세로 표지 1장 + 가로·세로 섞어서 | 쉬움 |
| C. 리스트형 | `list` | 번호 + 이름 + 사진 + 설명 + 정보가 반복 | "꼭 가볼 5곳" 같은 추천 모음 | 항목마다 1장 | 쉬움 |
| D. 코스형 | `course` | 시간표 세로선을 따라 장소가 이어지고, 장소 사이에 이동 방법 | 하루 일정, 동선 안내 | 장소마다 1장 + 지도 1장 | 보통 |
| E. 풀페이지형 | `fullpage` | 어두운 배경, 화면 가득한 장면을 한 장씩 넘김 | 사진이 강한 기사, 순위 모음 | 장면마다 **세로 9:16** | 보통 |
| F. 카드뉴스형 | `cards` | 4:5 카드를 옆으로 넘김 | SNS로 퍼질 기사 | 카드마다 **4:5** | 보통 |

고르는 기준
- 같은 장소 다섯 곳이라도 "어디가 좋은가"를 말하면 리스트형, "어떤 순서로 가는가"를 말하면 코스형이다
- 카드뉴스형의 4:5 카드는 Meta 광고 소재 비율과 같아서 광고 이미지로 다시 쓸 수 있다
- 처음 만드는 팀은 블로그형이나 리스트형부터 시작한다

## 2. 모든 유형 공통

### 위에서 아래 순서
1. 공통 상단 바 (한경닷컴 제공, 수정 금지). "한경 웹진 메인으로" 링크는 `../../index.html`
2. 공통 틀의 헤더 + 메뉴(GNB): `규칙/공통틀.md` 그대로. **서브메인·다른 유형과 글자 하나까지 같다.** 어떤 유형도 헤더를 사진 위에 겹쳐 올리지 않는다
3. 머리 정보: 키커 → 제목 → 글쓴이·날짜 → 공유 버튼
4. **요약 먼저:** 본문 맨 앞에 2~4줄 요약. 굵은 글씨 18px / 500 / 행간 32px (실측, 모바일 16px)
5. 유형별 본문 (3번)
6. 기사 끝: CTA 띠 → 관련 기사 → "웹진 첫 화면으로"
7. 공통 틀의 푸터 (`규칙/공통틀.md` 그대로)

### 머리 정보

| 요소 | PC | 모바일 (제안) |
|---|---|---|
| 키커 | 16px / 700 / `--c-accent` (제안) | 14px / 700 |
| 제목 | 48px / 700 / 행간 72px (실측) | 26px / 700 / 행간 36px |
| 날짜 | 14px / 400 / `--c-text-sub` (실측), `YYYY.MM.DD` | 13px |
| 글쓴이 | 24px 원형 프로필 + 이름 14px (실측) | 같음 |
| 공유 | 링크 복사 아이콘 버튼 1개 (실측 36×36, 모바일은 44×44) | 44×44 |

### 기사 끝
- **CTA 띠:** 배경 `--c-bg-gray`, 문장 18px / 700(`우리웹진.md`의 '권하는 문장') + CTA 버튼(`우리웹진.md`의 'CTA 문구', 배경 `--c-navy`, 흰 글자 16px / 700, 높이 48px, 알약형). 서브메인 CTA와 같은 곳으로 연결한다 (샘플: `../index.html#subscribe`)
- **관련 기사:** 타이틀 16~18px / 700, 아래 20px. 항목마다 제목 16~18px / 500 + 요약 13px / `--c-text-sub` + 날짜 12px, 오른쪽 썸네일 100×56 (실측 목록형). 내용은 그 기사의 `글.md`(제목·한 줄 요약·날짜·대표 사진)에서 가져온다. 그 기사의 `글.md`가 아직 없으면 넣지 않고 알려준다 (서브메인을 만들 때 다시 맞춘다)
- **돌아가기:** "웹진 첫 화면으로" 외곽선 알약 버튼(테두리 1px `#585858`, 14px / 700, 높이 44px) → `../index.html`

### 기본 정보 표 (여행 기사)
장소를 다루는 기사는 본문 끝에 기본 정보 표를 둔다.

```html
<dl class="info">
  <div><dt>주소</dt><dd>[글.md 사실 정보의 주소]</dd></div>
  <div><dt>입장료</dt><dd>[글.md 사실 정보의 요금]</dd></div>
  <div><dt>운영 시간</dt><dd>[글.md 사실 정보의 시간]</dd></div>
  <div><dt>문의</dt><dd>[글.md 사실 정보의 연락처]</dd></div>
</dl>
```
- 항목 이름 칸 폭 96px, 위아래 구분선 1px `--c-line`, 15px (제안)
- **바뀔 수 있는 정보**(운영 시간, 요금, 휴무)는 확인한 날짜를 함께 적는다 (예: "2026년 10월 확인 기준"). 출처마다 값이 다르면 숫자 대신 "방문 전 확인"으로 쓴다
- 시간표처럼 우리가 정한 예시는 "예시"라고 밝힌다

### 사진 공통
- 모서리 없음, 꽉 채우기 (실측)
- 캡션은 사진 아래 10px, 왼쪽 정렬, 13~14px / `--c-text-sub` (실측). 직접 찍지 않은 사진은 캡션 끝에 출처 (예: `사진: 한국관광공사`)
- 사진 위에 글자를 올릴 때는 아래쪽에 `--c-photo-scrim` 받침을 깔아 흰 글자 명도 대비 4.5:1을 지킨다

### 사진 파일 이름과 유형별 필요한 사진
파일 이름: `기사id-용도-비율.jpg` (영문 소문자, 숫자, 하이픈). 기사 대표 사진은 `기사id-16x9.jpg`로, 서브메인 기사 카드와 같은 파일을 쓴다.

모든 유형은 **서브메인 카드에 쓸 대표 사진 16:9를 1장 꼭** 준비한다 (풀페이지형·카드뉴스형 포함).

| 유형 | 필요한 사진 |
|---|---|
| 블로그형 | 대표 16:9 1장 + 본문 사진 2~4장 (16:9 또는 4:5 세로) |
| 매거진 커버형 | 표지 16:9(PC, `기사id-16x9.jpg`)와 4:5(모바일, `기사id-4x5.jpg`) + (선택) 화면 끝까지 닿는 사진 16:9, 나란히 놓을 4:5 2장 |
| 리스트형 | 대표 16:9 + 항목마다 16:9 1장 (`기사id-item1-16x9.jpg`) |
| 코스형 | 대표 16:9 + 지도 16:9 1장 (`기사id-map-16x9.jpg`) + 장소마다 16:9 1장 (`기사id-stop1-16x9.jpg`) |
| 풀페이지형 | 표지 16:9(PC)와 9:16(모바일) + 장면마다 9:16(모바일)과 16:9(PC) 한 쌍 (`기사id-scene1-9x16.jpg`, `기사id-scene1-16x9.jpg`) |
| 카드뉴스형 | 대표 16:9 1장 + 사진 카드마다 4:5 1장 (`기사id-card1-4x5.jpg`). 글자 카드는 사진 없음 |

- 사진은 `규칙/사진정리.md`대로 `tools/photo.py`로 자른다. 크기 · 용량은 도구가 지키고, 원본보다 크게 늘리지 않는다
- **원본이 표시 폭보다 작은 사진**(예: 가로 516px 사진을 620px 자리에)은 늘리지 않고 원래 크기로 가운데에 둔다. `<img>`에 `class="natural"`을 붙인다
- 출처와 라이선스 규칙, `images/credits.txt` 기록 방법은 서브메인 md 8번을 따른다

### 영상 공통
사진 자리에 영상을 쓸 수 있다. 영상도 사진과 같은 비율·캡션 규칙을 따른다.

**기준 한 줄: 소리 있는 영상은 YouTube, 짧은 무음 배경 영상과 배경음악은 저장소.**

| 구분 | 배경 영상 | 보는 영상 | 배경음악 |
|---|---|---|---|
| 예 | 히어로 배경, 풀페이지 장면, 영상 카드, 리스트·코스 항목 | 인터뷰, 브이로그, 코스 소개 | 풀페이지형·매거진 커버형의 분위기 음악 |
| 올리는 곳 | 저장소 `public/media/` | YouTube | 저장소 `public/media/` |
| 형식 | MP4(H.264), 720p, 15초 이내, **무음**, 파일당 8MB 이하 (서브메인 히어로는 5MB 이하) | YouTube 영상 ID | MP3, 128kbps, 파일당 3MB 이하 |
| 재생 | 자동 재생·반복·무음 | 누르면 재생 | **누르면 재생. 자동 재생 금지** |
| 첫 화면 | 포스터 사진 먼저 (`poster`) | 썸네일 + 재생 버튼만 먼저, 누르면 플레이어를 불러온다 | 소리 켜기 버튼만 보인다 |

### 배경 영상
- `<video src="./media/파일.mp4" poster="./images/포스터.jpg" autoplay muted loop playsinline preload="metadata">`
- 상대 경로로 넣는다. Cloudflare 작업 주소(파일당 25MB 한도)와 한경닷컴 서버 양쪽에서 똑같이 열린다
- 정지 버튼(44×44, 오른쪽 아래)을 둔다. 5초 넘게 움직이는 화면은 멈출 수 있어야 한다
- 사용자가 '움직임 줄이기'를 켠 경우(`prefers-reduced-motion`) 자동 재생하지 않고 포스터만 보여준다
- 영상에 소리 트랙이 있어도 무음으로만 쓴다. 음악이 필요하면 배경음악(MP3)을 따로 쓴다

### 보는 영상 (YouTube)
- 자막을 넣는다 (YouTube 자막 또는 영상에 입힌 자막)
- 처음에는 썸네일과 재생 버튼만 보여주고, 누르면 `youtube-nocookie.com` 플레이어를 불러온다. 페이지가 가벼워진다
- **서브메인 첫 화면에는 넣지 않는다.** 아래쪽 영상 섹션이나 상세페이지에 둔다. 광고로 들어온 사람이 YouTube로 빠져나가지 않게 하기 위해서다
- 세로 숏폼은 YouTube Shorts로 올리고 같은 방식으로 넣는다

### 배경음악
- 브라우저는 소리 있는 자동 재생을 막는다. **기본은 꺼짐**, 사용자가 "소리 켜기" 버튼을 눌렀을 때만 재생한다
- 소리 켜기·끄기 버튼(44×44, 화면 오른쪽 아래 고정, `aria-label` 필수)은 재생 중에도 항상 보이게 한다
- `<audio src="./media/파일.mp3" loop preload="none">`
- **서브메인(광고 랜딩)에는 넣지 않는다.** 상세페이지 중 풀페이지형·매거진 커버형에서만 선택해서 쓴다
- 웹 사용이 허용된 무료 음원만 쓴다. 출처와 라이선스를 `public/media/credits.txt`에 적는다

### 코드 (상세페이지. 클래스는 style.css에 있다)
```html
<!-- 무음 영상 -->
<figure class="clip"><video src="../media/페이지이름-clip1.mp4" autoplay muted loop playsinline preload="metadata" aria-label="설명"></video><button class="clip-stop" type="button" aria-label="영상 멈추기" aria-pressed="false">❚❚</button><figcaption>설명</figcaption></figure>
<!-- YouTube -->
<figure><button class="yt" type="button" data-youtube-id="영상ID" data-track="video_play" aria-label="설명 재생"><img src="https://i.ytimg.com/vi/영상ID/hqdefault.jpg" alt=""><span class="play" aria-hidden="true"><svg width="28" height="28" viewBox="0 0 24 24"><path d="M8 5v14l11-7z" fill="#fff"/></svg></span><span class="yt-note"></span></button><figcaption>설명</figcaption></figure>
<!-- 배경음악: 푸터 바로 앞 -->
<audio class="bgm" src="../media/페이지이름-bgm.mp3" loop preload="none"></audio><button class="bgm-toggle" type="button" data-track="bgm_on" aria-label="소리 켜기" aria-pressed="false">♪</button>
```
- 멈춤 · 소리 버튼과 '움직임 줄이기'는 `js/site.js`가 처리한다

### 공통
- **세로 영상(9:16) 하나를 여러 곳에 같이 쓴다:** 서브메인 모바일 히어로(배경 영상) + Meta Reels 광고(광고 관리자에 직접 업로드) + YouTube Shorts. 광고와 첫 화면이 같은 장면이면 이탈이 줄어든다
- 사람이 나오는 영상은 초상권 동의에 영상이 포함됐는지 확인한다
- `영상/`에는 15초 이내 무음 mp4(8MB 이하)만 넣는다. 긴 영상 · 소리 있는 영상은 YouTube에 올리고 주소를 `영상/유튜브.txt`에 적는다
- 측정: YouTube 썸네일 클릭 `data-track="video_play"`, 배경음악 켜기 `data-track="bgm_on"`. YouTube 재생·완료는 GTM의 YouTube 동영상 트리거로 잡는다

### 모바일 공통 (제안)
- 기준 폭 767px 이하, 좌우 여백 20px
- 상단 바 · 헤더 · 메뉴 · 푸터는 고정 영역: PC와 같은 구성 · 같은 글자 (`규칙/공통틀.md` 0번)
- 누르는 요소는 높이 44px 이상
- 본문 글자는 16px 아래로 줄이지 않는다

## 3. 유형별 규칙

### A. 블로그형 `blog` (한경트래블 기사 페이지 기반)
- 본문 폭 680px 가운데, 18px / 400 / 행간 32px (실측). 문단 사이 32px (제안)
- 대표 사진: 머리 정보 아래, 16:9, PC 폭 820px (제안)
- 소제목: 22px / 700, 위 48px·아래 16px (제안. 한경트래블은 본문 굵은 글씨 18px / 500으로 대신함, 실측)
- 본문 사진: 폭 620px 가운데, 위아래 30px (실측)
- 구분선: 폭 620px, 1px `#888888`, 위아래 30px (실측)
- 한경트래블의 좌우 사이드 칸은 쓰지 않는다
- 영상: 본문 폭(680px) 안에 YouTube 영상(16:9). 세로 Shorts는 폭 360px 가운데

### B. 매거진 커버형 `magazine`
- 표지: 화면 끝까지 닿는 사진. 모바일 세로 4:5, PC 16:9 폭 100% (제안)
- 표지 아래쪽 받침 위에 흰색으로 배지(지역·카테고리, 14px / 700, 높이 28px, 알약형, 실측 형태) → 제목(모바일 30px, PC 48px / 700) → 한 줄 소개 → 글쓴이·날짜
- 큰 인용문: 가운데 정렬, 22px(모바일)·28px(PC) / 500, 위에 폭 40px·두께 2px `--c-accent` 짧은 선 (제안)
- 화면 끝까지 닿는 사진: 본문 여백을 무시하고 화면 폭 전체 (제안)
- 사진 두 장 나란히: 2단, 간격 8px, 세로 4:5 (제안)
- 본문 글자 규칙은 블로그형과 같다
- 영상: 표지를 짧은 배경 영상으로 바꿀 수 있다. 화면 끝까지 닿는 사진 자리에 영상을 넣어도 된다
- 배경음악(선택): 소리 켜기 버튼으로만 재생

### C. 리스트형 `list`
- 항목 3~10개. 항목 사이 위쪽 1px `--c-line`, 위아래 여백 28px (제안)
- 항목 순서: 번호 + 이름 → 사진(16:9) → 설명 → 정보 줄
  - 번호: 28px / 700 / `--c-accent` (제안)
  - 이름: 20px(모바일)·24px(PC) / 700
  - 설명: 15~16px / 행간 26~28px
  - 정보 줄: 13px / `--c-text-sub`, 앞에 선 아이콘(시계, 위치) (제안)
- PC에서는 사진 왼쪽(폭 50%) + 글 오른쪽으로 놓아도 된다 (제안)
- 영상: 항목 사진 자리에 짧은 무음 영상(16:9)을 넣을 수 있다

### D. 코스형 `course`
- 제목 아래 **코스 요약 표**: 3칸(장소 수 / 이동 수단 / 소요 시간), 칸 이름 12px / `--c-text-sub`, 값 16px / 700, 테두리 1px `--c-line` (제안)
- 요약 표 아래 동선 지도 이미지 1장 (16:9 또는 4:3)
- **타임라인:** 왼쪽 시간 칸(폭 64px, 14px / 700 / `--c-accent`) + 세로선(2px `--c-line`) + 오른쪽 내용 (제안)
  - 내용: 장소 이름 18px / 700 → 사진(16:9) → 설명 14px / 행간 22px
  - 장소 사이: 아래 화살표 아이콘 + 이동 방법 13px / `--c-text-sub` (예: "버스 15분")
- 마지막 장소에는 이동 안내를 넣지 않는다
- 영상: 장소 사진 자리에 짧은 무음 영상을 넣을 수 있다. 이동 장면(버스 창밖, 걷는 길)을 짧게 넣으면 동선이 잘 전달된다

### E. 풀페이지형 `fullpage` (한경트래블 트래블 PICK! 기반)
- 배경 `--c-bg-dark` (실측). 장면 하나가 화면 높이 전체 (실측). 장면 수는 표지·마무리를 빼고 5~10개 (실측)
- 공통 틀(상단 바·헤더·메뉴)은 다른 유형과 똑같이 맨 위에 두고 색도 같다. 표지 장면은 헤더 아래에서 시작한다. 문서 전체(`<html class="fp-html">`)에 스크롤 스냅을 걸고, 상단 바에 `scroll-snap-align: start`, 푸터에 `scroll-snap-align: end`를 붙여 맨 위·맨 아래에서 공통 틀이 보이게 한다
- 장면 사진은 `<picture>`로 모바일 9:16, PC 16:9를 나눠 넣는다
- 장면 넘김은 CSS 스크롤 스냅(`html.fp-html`에 `scroll-snap-type: y mandatory`, 장면마다 `height: 100svh`)으로 만든다. 별도 라이브러리는 쓰지 않는다 (제안)
- 장면 글자 (PC / 모바일)
  - 표지 제목 48px / 30px, 700, 흰색 (실측 47.5px)
  - 순서 라벨("No.1  09:00") 20px / 15px, `--c-text-on-dark-sub` (실측)
  - 항목 이름 56px / 32px, 400, 흰색 (실측)
  - 한 줄 설명 28px / 18px, 흰색 (실측)
  - 본문 16px / 15px, 흰색 (실측 크기)
- 글자는 왼쪽 아래, 사진 위 `--c-photo-scrim` 받침 위에 둔다
- 오른쪽 위에 장면 번호("1 / 5")
- 마지막 장면: CTA 버튼은 흰 배경 + 검정 글자(어두운 배경에서 잘 보이게), 관련 기사는 흰 글자 목록, 돌아가기는 흰 테두리 버튼 (제안)
- **모바일은 장면마다 세로 사진(9:16)이 필수다**
- 영상: **풀페이지형에 가장 잘 맞는다.** 장면 배경을 짧은 무음 세로 영상(9:16)으로 바꿀 수 있다. 화면에 보이는 장면의 영상만 재생하고, 지나간 장면은 멈춘다
- 배경음악(선택): 표지 장면에 소리 켜기 버튼을 두고, 누르면 마지막 장면까지 이어서 재생

### F. 카드뉴스형 `cards`
- 카드 6~10장, 비율 4:5. 모바일 카드 폭 330px, PC 폭 480px (제안)
- 첫 카드: 표지(제목이나 핵심 문장). 마지막 카드: CTA 안내
- 카드 한 장에 문장 하나만 쓴다
- 카드 아래: 이전·다음 버튼(44×44 원형, 테두리 1px `--c-line`) + 가운데 번호("1 / 7")
- 다음 카드 일부가 오른쪽에 보이게 해서 넘길 수 있다는 걸 알린다 (제안)
- 넘김은 CSS 가로 스크롤 스냅으로 만든다. 버튼은 같은 스크롤을 움직이기만 한다 (제안)
- 카드 아래 짧은 본문 2~3줄 (한 줄 요약), 사실 정보가 있으면 기본 정보 표
- 카드 이미지는 광고 소재(4:5)로 다시 쓸 수 있도록 글자를 이미지가 아니라 HTML로 올린다. 광고용은 따로 캡처한다
- 영상: 카드 일부를 짧은 무음 영상 카드(4:5)로 만들 수 있다. 화면에 보이는 카드의 영상만 재생한다

## 4. 필수 요소

- 경로는 상대 경로로만 쓴다. 상세페이지는 `articles` 폴더 안에 있으므로 `../`로 올라간다
- 폴더로 끝나는 링크(`../`) 대신 `index.html`까지 쓴다. 서버뿐 아니라 내 컴퓨터에서 파일을 더블클릭해 열어도 동작한다
  - 서브메인: `../index.html`
  - 웹진메인(공통 상단 바): `../../index.html`
  - 사진: `../images/사진이름.jpg`
  - 스타일·스크립트: `../css/style.css`, `../js/site.js`
  - 다른 기사: `./다른기사.html`
  - `/`로 시작하는 경로 금지. Cloudflare 작업 주소와 한경닷컴 서버 양쪽에서 똑같이 열려야 한다
- `<title>`(기사 제목 | 웹진 이름), `<meta name="description">`(요약)
- 공유 미리보기(OG): `og:type` `article`, 제목·요약·이미지. 이미지는 그 기사의 대표 사진(대표 또는 대표(PC), 16:9)을 쓴다. 이 주소만 실제 주소(`https://lxwebzine.hankyung.com/teamN/images/...`)로 쓴다
- 대표 주소(canonical): `https://lxwebzine.hankyung.com/teamN/articles/기사이름.html`
- 한경 측정 코드 유지(삭제·수정 금지), 팀 GTM 코드
- 클릭 추적 이름표: `data-track="article_cta"`, `"related_article"`, `"back_to_submain"`, `"share_copy"`. 카드뉴스형은 `"card_next"`, `"card_prev"` 추가. 영상 재생은 `"video_play"`
- 사진마다 대체 텍스트(alt), 명도 대비 4.5:1 이상
- 새 기사를 만들면 서브메인 기사 카드에도 추가한다 (서브메인 md의 발췌 표시 규칙대로)

## 5. 콘텐츠 폴더 형식 (`콘텐츠/이름/`)

```
콘텐츠/
  우리웹진.md   웹진 정보 (팀에 하나)
  콘텐츠1/      콘텐츠 하나 = 폴더 하나. 이름은 학생이 바꾼다 (한글 가능)
    글.md       학생이 쓴 칸 + Claude Code가 채우는 칸
    사진/       학생이 넣은 원본 (파일 이름 자유)
    영상/       15초 이내 무음 mp4, 또는 유튜브.txt (YouTube 주소)
    뮤직/       배경음악 mp3 한 곡 (매거진 커버형 · 풀페이지형만)
```
- `글.md`가 있는 폴더가 모두 콘텐츠다. 유형 · 제목이 비어 있는 폴더(이름을 아직 안 바꾼 `콘텐츠1` 등)는 빼고 알려준다
- 각 폴더의 `넣는법.txt`는 안내라서 원본으로 쓰지 않는다
- 새 폴더를 만들어 달라고 하면 `규칙/글양식.md`를 `글.md`로 복사하고 빈 `사진/` · `영상/` · `뮤직/`을 만든다

**글.md의 칸** — `## 칸 이름`은 바꾸지 않는다. `<!-- -->` 안의 안내는 읽지 않는다. `---` 아래는 Claude Code가 채운다.

| 칸 | 누가 | 쓰는 것 | 페이지에서 |
|---|---|---|---|
| 유형 | 학생 | 블로그형 · 매거진 커버형 · 리스트형 · 코스형 · 풀페이지형 · 카드뉴스형 | 3번 유형 규칙 |
| 제목 · 카테고리 | 학생 | 카테고리는 `우리웹진.md` 메뉴 카테고리 중 하나 | 키커, 제목, 서브메인 카드 |
| 한 줄 요약 | 학생 (비우면 Claude Code가 본문 문장으로 제안) | 1~2문장 | 요약, 카드, 관련 기사, description · OG |
| 날짜 | 학생 (비우면 만든 날) | `2026-10-15` | 메타 정보, 카드 |
| 본문 | 학생 (사진 · 영상 자리 표시만 Claude Code) | 자유롭게. 아래 표기 | 본문 |
| 사실 정보 | 학생 | `- 항목: 값`, 마지막 줄 `- 확인: 날짜, 확인한 곳` | 기본 정보 표 + "…확인 기준" |
| 출처 | 학생 | 직접 찍거나 만들지 않은 사진 · 영상 · 음악만 `- 파일: 출처, 라이선스, 주소`. 음악은 꼭 적는다 | credits.txt, 캡션 끝 출처 |
| 페이지 이름 | Claude Code | 영문 소문자 · 하이픈 (예: `saebyeol-oreum`) | `public/articles/페이지이름.html` |
| 사진 | Claude Code | `- 역할: 만든 파일 \| 사진 설명 \| 원본 파일` (`규칙/사진정리.md` 4번) | 사진과 대체 텍스트 · 캡션 |
| 영상 · 음악 | Claude Code | `- 영상: 페이지이름-clip1.mp4 또는 YouTube 주소 \| 설명 \| 원본 파일`, `- 배경음악: 페이지이름-bgm.mp3 \| 설명 \| 원본 파일` | 영상 자리, 소리 켜기 버튼 |

- 글쓴이는 `우리웹진.md`의 글쓴이를 쓴다
- 관련 기사는 다른 콘텐츠 중 날짜가 최신인 것 2개 (아직 페이지가 없는 콘텐츠는 빼고 알려준다)

**영상 · 음악 옮기기**
- mp4: `public/media/페이지이름-clip1.mp4`(둘째부터 clip2 …)로 옮긴다. 8MB를 넘거나 15초를 넘으면 쓰지 않고 YouTube에 올리라고 알려준다
- 영상 코덱이 H.264가 아니면(아이폰 기본 HEVC 등) 브라우저에 따라 재생되지 않는다. 그대로 쓰지 않고 알려준다 (ffmpeg가 있으면 H.264로 바꿔 써도 된다)
- `유튜브.txt`: 줄마다 YouTube 주소. 옮기지 않고 본문 `[영상: 주소]`로 넣는다
- mp3: `public/media/페이지이름-bgm.mp3`로 옮긴다. 3MB 이하, 매거진 커버형 · 풀페이지형에서만. `## 출처`에 없으면 쓰지 않고 알려준다
- 옮긴 파일은 `public/media/credits.txt`에 `파일 이름 | 출처 | 라이선스 | 원본 주소`로 적는다 (직접 찍은 영상은 `직접 촬영(팀번호) | - | -`)

**사진 역할**

| 역할 | 유형 | 쓰는 곳 |
|---|---|---|
| 대표 | 블로그형 · 리스트형 · 코스형 · 카드뉴스형 | 대표 사진 16:9. 서브메인 카드 · 관련 기사 썸네일 · OG |
| 대표(PC) · 대표(모바일) | 매거진 커버형 · 풀페이지형 | 표지 (`<picture>`). 대표(PC) 16:9가 서브메인 카드 · 관련 기사 · OG 사진 |
| 본문 | 블로그형 · 매거진 커버형 | 본문 사진 |
| 본문 넓게 | 매거진 커버형 | 화면 끝까지 닿는 사진 |
| 항목 · 장소 · 카드 | 리스트형 · 코스형 · 카드뉴스형 | 본문 `[사진: ]` 자리 |
| 지도 | 코스형 | 코스 요약 표 아래 동선 지도 |
| 장면 | 풀페이지형 | `- 장면: 9x16파일, 16x9파일 \| 설명 \| 원본` 한 쌍. 본문 `[사진: 9x16파일]`이 그 장면 |

**본문 표기** — 학생은 글자 표기만, 사진 표기는 Claude Code가 넣는다 (학생이 넣어도 된다)

| 표기 | 뜻 | 유형 |
|---|---|---|
| `### 제목` | 덩어리 하나의 시작. 블로그형 · 매거진 커버형은 소제목, 리스트형은 항목(`### 1. 이름`), 코스형은 장소(`### 09:00 이름`), 풀페이지형은 장면, 카드뉴스형은 카드(`### 카드`) | 모두 |
| `> 문장` | 크게 강조할 문장 | 블로그형 · 매거진 커버형 |
| `- 이름: 값` | 정보 줄. 리스트형은 항목 아래, 코스형은 본문 맨 앞 세 줄(코스 요약 표) | 리스트형 · 코스형 |
| `→ 문장` | 다음 장소까지 이동 방법 | 코스형 |
| `[사진: 파일]` | 사진 한 장 | 모두 |
| `[사진 두 장: 파일, 파일]` | 같은 크기로 나란히 | 블로그형 · 매거진 커버형 |
| `[사진 넓게: 파일]` | 화면 폭 끝까지 | 매거진 커버형 |
| `[영상: 파일.mp4]` · `[영상: YouTube 주소]` | 무음 영상 (자동 재생 · 멈춤 버튼) · YouTube (썸네일, 누르면 재생) | 블로그형 · 매거진 커버형 · 리스트형 · 코스형 |

- 글에 없는 사실(주소, 요금, 운영 시간, 인용)은 만들지 않는다. 글은 다듬기만 하고 뜻은 바꾸지 않는다. 학생이 쓴 문장 사이에 사진 · 영상 표기 줄만 넣는다
- 학생이 `[사진: 원본 파일 이름]`을 썼으면 그 자리에 그 원본으로 자른 파일을 넣고 표기를 만든 파일 이름으로 바꾼다
- 카드뉴스형에서 `### 카드` 아래 사진이 없으면 남색 바탕 글자 카드
- 코스형의 시각은 팀이 정한 예시다. 타임라인 위에 "시각은 예시입니다"를 적는다

## 6. 팀이 정하는 것과 바꾸지 않는 것

| 팀이 정한다 | 바꾸지 않는다 |
|---|---|
| 기사마다 유형 | 디자인 토큰(색, 서체, 간격) |
| 사진, 문구, 소제목, 항목 수 | 사진 비율과 모서리 없음 |
| 관련 기사로 연결할 기사 | 요약 먼저, 기사 끝 CTA와 돌아가기 |
| | 필수 요소(4번) |
