# 서브메인 규칙 (Claude Code가 읽는다)

- **학생은 이 파일을 고치지 않는다.** 학생은 `콘텐츠/우리웹진.md`를 채운다. 서브메인용 폴더는 없다. Claude Code가 콘텐츠 폴더들을 읽어 만든다
- Claude Code는 서브메인을 만들 때 이 규칙, `규칙/공통틀.md`, `규칙/사진정리.md`, `콘텐츠/우리웹진.md`, 모든 콘텐츠 폴더의 `글.md` · `사진/`, 만든 상세페이지를 함께 읽는다
- 파일: `public/index.html`
- 테스트 주소: 우리 팀 Cloudflare 작업 주소 (GitHub에 올리면 자동 반영)
- 실제 주소: `lxwebzine.hankyung.com/teamN/` (한경닷컴이 검수 후 서버에 올린다. 주소 끝의 `/`까지 포함)
- 역할: 우리 팀 웹진의 첫 페이지이자 **광고 랜딩페이지**. 광고를 눌러 들어온 사람이 첫 화면에서 무엇을 하면 되는지 바로 알 수 있어야 한다. 또 웹진메인은 이 페이지의 내용을 발췌해 보여준다 (7번).
- 기준: 한경트래블 채널 메인(hankyung.com/travel)의 화면 레이아웃과 색감. (실측)은 한경트래블에서 측정한 값, (제안)은 새로 정한 값이다.
- 샘플 페이지: 샘플 웹진의 `team1/index.html`

### 폴더 구조
```
public/                ← 이 폴더 내용이 그대로 lxwebzine.hankyung.com/teamN/ 이 된다
├── index.html         서브메인 (이 md)
├── site.json          {"team": "teamN", "name": "웹진 이름"}
├── articles.json      외부 게재 기사 목록 (⑤ 외부 게재 기사를 쓸 때만)
├── css/style.css      디자인 토큰과 공통 스타일. 서브메인과 상세페이지가 함께 쓴다
├── js/site.js         링크 복사, YouTube 누르면 재생, 모바일 하단 고정 CTA
├── images/            사진과 credits.txt (8번 이미지 규칙)
├── media/             배경음악 mp3와 credits.txt (9번 영상 규칙)
└── articles/          상세페이지 (상세페이지 md)
```
- 색·글자·간격은 `css/style.css` 한 곳에만 적고, 페이지마다 다시 적지 않는다

## 0. 서브메인을 만드는 재료

| 곳 | 서브메인에서 쓰이는 곳 |
|---|---|
| `우리웹진.md` 팀 번호 | OG · canonical의 실제 주소 `https://lxwebzine.hankyung.com/팀번호/`, `site.json`의 team |
| `우리웹진.md` 웹진 이름 · 한 줄 소개 · 메뉴 카테고리 | 공통 틀의 헤더 · 메뉴 · 푸터 (`규칙/공통틀.md`), `site.json`, description 앞부분. 카테고리마다 첫 카드에 `id="cat-N"` |
| `우리웹진.md` CTA 문구 | ① 히어로 버튼, 휴대폰 하단 고정 버튼, ⑥ 구독 띠 버튼 (상세페이지 끝 버튼도 같다). 누르면 `#subscribe` |
| `우리웹진.md` 권하는 문장 · 받는 것 | ⑥ 구독 띠의 제목 · 설명 (상세페이지 끝 CTA 띠 문장도 같다) |
| `우리웹진.md` 광고 문구 · 리드 한 줄 · 배지 | ① 히어로 제목 · 리드 · 배지, `<title>`, description, OG. 비어 있으면 대표 콘텐츠의 제목 · 한 줄 요약에서 제안해 채우고 알려준다 |
| `우리웹진.md` 대표 콘텐츠 | ② 대표 기사 (콘텐츠 폴더 이름 → 그 글.md). 비어 있으면 날짜가 최신인 콘텐츠 |
| `우리웹진.md` 한눈에 띠 | ① 아래 한눈에 띠 (줄이 없으면 넣지 않는다) |
| 대표 콘텐츠 폴더의 `사진/` (맞는 사진이 없으면 다른 콘텐츠 폴더) | ① 히어로 PC(16:9) · 휴대폰(4:5), 공유 미리보기. Claude Code가 골라 잘라 `우리웹진.md`의 첫 화면 사진 칸에 적는다 (원본: `폴더/사진/파일`). 칸이 이미 채워져 있으면 그대로 쓴다 (바꾸려면 학생이 말로 요청) |
| 각 `글.md`의 대표 사진(대표 또는 대표(PC)) · 카테고리 · 제목 · 한 줄 요약 · 날짜 | ② 대표 기사, ③ 기사 카드 (콘텐츠 폴더마다 하나, 날짜 최신순. 비어 있는 폴더는 뺀다) |

- `우리웹진.md`와 글.md에 없는 문구는 쓰지 않는다. 비어 있는 칸은 `[ ]`로 두고 알려준다
- `<title>`: `웹진 이름 | 광고 문구`, description: `한 줄 소개. 리드 한 줄`
- ④ 테마 패널, ⑤ 외부 게재 기사, 영상 섹션은 기본으로 넣지 않는다. 팀이 원하면 강사와 상의해 `우리웹진.md`에 칸을 더한다

## 1. 디자인 토큰

웹진메인·상세페이지 md와 같은 값을 쓴다. **팀이 바꿀 수 없다.** 바꿔야 할 이유가 있으면 강사와 상의한다.

```css
:root {
  --c-text: #121212;        /* 기본 텍스트 (실측) */
  --c-text-sub: #585858;    /* 날짜, 리드, 캡션 (실측) */
  --c-text-weak: #888888;
  --c-accent: #D6403B;      /* 키커·강조 (실측) */
  --c-navy: #142C67;        /* 채움 버튼·CTA (실측) */
  --c-logo-navy: #002D74;   /* 웹진 이름 (실측 로고 색) */
  --c-error: #EA2D44;       /* 오류 표시 전용 */
  --c-bg: #FFFFFF;
  --c-bg-tint: #FEF5F5;     /* 테마 패널 배경 (실측) */
  --c-bg-gray: #F7F7F7;     /* 회색 띠 영역 (실측) */
  --c-line: #DDDDDD;        /* 구분선 1px (실측) */
  --font: -apple-system, system-ui, "Noto Sans KR", "Apple SD Gothic Neo", "Malgun Gothic", "Segoe UI", Roboto, sans-serif;
  --tracking: -0.03em;
  --container: 1200px;      /* (실측) */
  --gap-module: 64px;       /* 섹션 사이 (실측) */
  --gap-grid: 60px;         /* 카드 사이 (실측) */
  --r-img: 0;               /* 사진 모서리 없음 (실측) */
  --r-pill: 400px;          /* 버튼·배지 (실측) */
  --ease: cubic-bezier(0, 0, 0.2, 1);
}
```

### 타입 스케일

| 용도 | PC | 모바일 (제안) |
|---|---|---|
| 히어로 제목 (사진 위, 흰색) | 48px / 700 / 행간 60px (실측) | 28px / 700 / 행간 38px |
| 피처 카드 제목 | 48px / 700 (실측) | 24px / 700 |
| 섹션 타이틀 | 32px / 700 (실측) | 22px / 700 |
| 카드 제목 | 24px / 500 (실측) | 18px / 500 |
| 키커 | 20px / 700 / `--c-accent` (실측) | 14px / 700 |
| 리드 | 16px / 400 / 행간 24px / `--c-text-sub`, 3줄 말줄임 (실측) | 15px / 400 |
| 버튼 | 14px / 700 (실측), CTA는 16px / 700 (제안) | 16px / 700 |
| 날짜 | 16px / 400 / `--c-text-sub` (실측) | 13px / 400 |

굵기는 400, 500, 700만 쓴다.

## 2. 페이지 구성 (위에서 아래 순서)

한 줄로 세로로 내려가는 **1단 구성**이다. 한경트래블 메인에 있는 지도, 오른쪽 사이드바, 긴 뉴스 목록은 쓰지 않는다. 광고로 들어온 사람의 시선이 흩어지기 때문이다.

```
┌──────────────────────────────────────────┐
│ 공통 상단 바 (템플릿 제공, 수정 금지)        │
├──────────────────────────────────────────┤
│ 공통 틀: 헤더 + 메뉴 (규칙/공통틀.md)       │
├──────────────────────────────────────────┤
│ ① 히어로: 사진 + 제목 + 리드 + CTA 버튼  [필수] │
├──────────────────────────────────────────┤
│ ② 대표 기사: 피처 카드 1~2개          [필수] │
├──────────────────────────────────────────┤
│ ③ 기사 카드: 3단 그리드               [필수] │
├──────────────────────────────────────────┤
│ ④ 테마 패널: 연분홍 배경              [선택] │
├──────────────────────────────────────────┤
│ ⑤ 외부 게재 기사                     [선택] │
├──────────────────────────────────────────┤
│ 영상: 대표 영상 1개 또는 숏폼 3개      [선택] │
├──────────────────────────────────────────┤
│ ⑥ 구독·참여 CTA                      [필수] │
├──────────────────────────────────────────┤
│ 공통 틀: 푸터 (규칙/공통틀.md)              │
└──────────────────────────────────────────┘
```

### 공통 틀: 상단 바 · 헤더 · 메뉴(GNB) · 푸터 [필수]
- `규칙/공통틀.md`의 코드를 그대로 쓴다. **같은 팀의 상세페이지와 글자 하나까지 같다** (경로 앞부분만 다름)
- 웹진 이름 가운데 정렬, 28px / 700 / `--c-logo-navy` (제안)
- 메뉴(GNB)는 필수: 카테고리를 15px / 500, 항목 사이 16px (실측). 누르면 그 카테고리의 첫 카드로 간다 (첫 카드에 `id="cat-N"`)

### ① 히어로 [필수] — 한경트래블과 다른 부분
- 사진 1200×675(16:9), 모서리 없음 (실측)
- 사진 위 아래쪽에 흰색 제목 48px / 700, 그 위에 흰색 알약 배지(14px / 700, 높이 28px)로 지역·카테고리 (실측)
- 제목 아래 리드 한 줄(흰색 18px / 400) + **CTA 버튼 1개** (제안)
  - 채움 알약 버튼: 배경 `--c-navy`, 흰 글자 16px / 700, 높이 48px, 좌우 여백 28px
- 글자가 잘 보이도록 사진 아래쪽에 검정 그라데이션(투명 → 60%)을 깐다
- **슬라이더를 쓰지 않는다.** 한경트래블 메인은 3장 슬라이더지만, 랜딩페이지는 광고 문구와 같은 메시지 하나를 고정해서 보여줘야 한다
- 제목은 광고 문구와 같은 메시지로 쓴다 (0번 '광고 문구' 참고)
- 사진은 PC용 16:9(`이름-hero-16x9.jpg`)와 모바일용 4:5(`이름-hero-4x5.jpg`) 두 장을 준비하고 `<picture>`로 넣는다. 발췌 표시(`data-excerpt="image"`)는 16:9 `<img>`에 붙인다 (7번)
- **사진 대신 짧은 배경 영상을 쓸 수 있다** (9번 영상 규칙). PC는 16:9, 모바일은 세로 9:16 또는 4:5. 영상이 나와도 제목·리드·CTA는 그대로 위에 보여야 하고, 포스터 사진이 먼저 떠야 한다. 히어로 영상은 5MB 이하로 줄인다

### 한눈에 띠 [선택] — ① 바로 아래
- 숫자나 짧은 말 3~4개와 설명 한 줄씩 (예: "23m · 물줄기 높이")
- 배경 `--c-navy`, 숫자 32px / 700 흰색, 설명 14px. 칸 사이 세로 선. 컨테이너 폭(1200px)
- 모바일은 2칸씩 두 줄. 숫자 24px

### ② 대표 기사 [필수]
- 피처 카드 1~2개 (실측 '여행의 모든 설레임' 형태)
  - 사진 1200×675
  - 사진 아래쪽에 폭 940px 흰 상자가 80px 겹쳐 올라온다. 상자 안쪽 여백 위 40px, 좌우 60px
  - 상자 안: 제목 48px / 700 + 리드 16px, 3줄 말줄임
- 누르면 해당 상세페이지로 이동
- 대표 기사는 ③ 기사 카드에도 함께 넣어도 된다. 웹진메인은 같은 기사를 한 번만 보여준다

### ③ 기사 카드 [필수]
- 섹션 타이틀 32px / 700 (실측), 타이틀 아래 24px 띄움 (제안)
- 3단 그리드: 카드 폭 360px, 간격 60px (제안, 3×360 + 2×60 = 1200)
- 카드: 사진 360×203(16:9) → 키커(카테고리) → 제목 24px / 500 → 날짜 16px / `--c-text-sub` (실측 '여행 잇!템' 형태)
- 대표 기사를 뺀 나머지 기사를 날짜 최신순으로 놓는다. 카드가 2개면 2단, 3개 이상이면 3단
- 상세페이지를 만들 때마다 카드를 추가하고 발췌 표시를 붙인다 (7번)
- 카드 사진은 그 기사의 대표 사진(16:9)을 그대로 쓴다
- **기사 유형과 관계없이 카드 모양은 하나다.** 블로그형이든 풀페이지형이든 카드에는 카테고리·제목·날짜·대표 사진(16:9)이 같은 자리에 들어간다. 정보는 각 콘텐츠의 `글.md`에서 가져온다

### ④ 테마 패널 [선택]
- 배경 `--c-bg-tint`, 안쪽 여백 위 70px / 아래 72px (실측 TRAVEL GUIDE 패널)
- 왼쪽: 대표 사진 700×394 + 제목 34px / 700
- 오른쪽: 흰 패널(폭 470px, 여백 25/30)에 항목 4개. 항목마다 키커 20px / 700 / `--c-accent` + 제목 24px / 500 + 썸네일 160×90 (실측)
- 한 가지 주제로 기사를 묶어 보여줄 때 쓴다 (예: "제주 동쪽 하루 코스")

### ⑤ 외부 게재 기사 [선택]
- `articles.json`의 `type: external` 기사
- 목록형: 썸네일 240×135 + 제목 20px / 500 + 요약 14px 2줄 + 날짜 (실측 목록형)
- 새 창으로 열고, 제목 끝에 "외부 기사" 표시. 링크에는 UTM을 붙인다 (UTM 규칙은 측정 교안 참조)

### 영상 섹션 [선택]
- 섹션 타이틀 32px / 700 (예: "영상으로 보기")
- 둘 중 하나
  - 대표 영상 1개: YouTube, PC 16:9 폭 1200px / 모바일 폭 100%
  - 숏폼 3개: YouTube Shorts 3개를 세로 9:16 카드로 가로로 나란히(PC), 모바일은 가로로 넘김. 카드 폭 PC 360px, 모바일 200px
- 영상 아래 캡션 14px / `--c-text-sub`

### ⑥ 구독·참여 CTA [필수]
- 배경 `--c-navy` 전체 폭, 가운데 정렬. 제목·설명 흰색, 버튼은 흰 바탕에 남색 글자
- 한 줄 제목 24px / 700 (`우리웹진.md` 권하는 문장) + 설명 16px (받는 것) + 버튼 (CTA 문구)
- `id="subscribe"`. 히어로 CTA와 하단 고정 CTA가 여기로 온다
- 구독 기능은 한경 공통 기능 코드를 넣는다 (직접 만들지 않는다)

## 4. 모바일 규칙 (제안)

광고는 대부분 휴대폰에서 눌린다. **모바일 화면을 먼저 확인한다.**

- 기준 폭: 767px 이하 모바일, 768~1199px 태블릿, 1200px 이상 PC
- 상단 바 · 헤더 · 메뉴 · 푸터는 고정 영역: PC와 같은 구성 · 같은 글자 (`규칙/공통틀.md` 0번). 메뉴를 ☰로 숨기지 않는다
- 좌우 여백 20px, 섹션 사이 40px
- 히어로: 세로 사진(4:5)으로 바꿔 쓰고, 제목·리드·CTA 버튼이 **스크롤 없이 첫 화면 안에** 보여야 한다
- CTA 버튼: 폭 100%, 높이 48px
- 스크롤해서 히어로 CTA가 화면에서 사라지면, 화면 아래에 같은 CTA를 고정 버튼으로 띄운다
- 피처 카드: 흰 상자를 겹치지 않고 사진 아래에 붙인다. 상자 안쪽 여백 20px
- 기사 카드: 태블릿 2단, 모바일 1단
- 테마 패널: 대표 기사 위, 항목 목록 아래로 쌓기
- 누르는 요소는 높이 44px 이상

## 5. 필수 요소 (템플릿과 CLAUDE.md 기준)

- 경로는 상대 경로로만 쓴다 (`./articles/...`, `./images/...`, `./css/style.css`). `/`로 시작하는 경로 금지. Cloudflare 작업 주소와 한경닷컴 서버 양쪽에서 똑같이 열려야 한다
- 공통 상단 바의 "한경 웹진 메인으로" 링크는 `../index.html` (서브메인 한 단계 위가 웹진메인). 웹진 이름 링크는 `./index.html`
- 폴더로 끝나는 링크(`../`, `./`) 대신 `index.html`까지 쓴다. 내 컴퓨터에서 파일을 더블클릭해 열어도 동작한다
- `<title>`, `<meta name="description">`
- 공유 미리보기(OG) 제목·설명·이미지. 이미지는 1200×630 `이름-og.jpg`. 이 주소만 실제 주소(`https://lxwebzine.hankyung.com/teamN/images/이름-og.jpg`)로 쓴다
- 대표 주소(canonical): `https://lxwebzine.hankyung.com/teamN/`
- 한경 측정 코드 유지 (삭제·수정 금지), 팀 GTM 코드
- 클릭 추적 이름표
  - 히어로 CTA: `data-track="hero_cta"`
  - 하단 고정 CTA: `data-track="sticky_cta"`
  - 기사 카드: `data-track="article_card"`
  - 외부 기사: `data-track="external_article"`
  - 구독: `data-track="subscribe"`
  - YouTube 재생: `data-track="video_play"`
- 사진마다 대체 텍스트(alt), 명도 대비 4.5:1 이상
- 웹진메인 발췌 표시 (7번)
- 광고 랜딩 주소는 실제 주소 `lxwebzine.hankyung.com/teamN/`만 쓴다. Cloudflare 작업 주소를 광고에 넣지 않는다

## 7. 웹진메인 발췌 표시 (필수)

웹진메인은 이 페이지를 직접 읽어서 아래 표시가 붙은 부분만 꺼내 보여준다. 서브메인을 고치면 웹진메인에도 자동으로 반영된다. 표시가 빠지면 웹진메인에서 우리 팀 카드가 비게 된다.

```html
<!-- 히어로: 1개. 발췌 표시는 16:9 <img>에 붙인다 -->
<section data-excerpt="hero">
  <picture>
    <source media="(max-width: 767px)" srcset="./images/jeongbang-hero-4x5.jpg">
    <img data-excerpt="image" src="./images/jeongbang-hero-16x9.jpg" alt="바다로 떨어지는 정방폭포">
  </picture>
  <h1 data-excerpt="title">바다로 떨어지는 폭포를 보러, 서귀포로</h1>
  <p data-excerpt="lead">높이 23m 물줄기가 바다로 곧장 떨어지는 정방폭포에서 반나절을 보낸다</p>
</section>

<!-- 대표 기사(피처 카드): data-featured="true". 날짜가 화면에 안 보여도 date 표시는 넣는다 -->
<a data-excerpt="article" data-featured="true" href="./articles/jeongbang-view.html">
  <img data-excerpt="image" src="./images/jeongbang-view-16x9.jpg" alt="...">
  <span data-excerpt="kicker">시선</span>
  <h2 data-excerpt="title">정방폭포를 보는 세 가지 시선</h2>
  <time data-excerpt="date" datetime="2026-10-06" hidden>2026.10.06</time>
</a>

<!-- 기사 카드: 대표 기사를 뺀 나머지 기사 -->
<a data-excerpt="article" href="./articles/jeongbang-story.html">
  <img data-excerpt="image" src="./images/jeongbang-story-16x9.jpg" alt="...">
  <span data-excerpt="kicker">이야기</span>
  <h3 data-excerpt="title">바다로 곧장 떨어지는 폭포, 정방폭포</h3>
  <time data-excerpt="date" datetime="2026-10-07">2026.10.07</time>
</a>
```

- 표시 이름은 위의 것만 쓴다: `hero`, `article`, `image`, `title`, `lead`, `kicker`, `date`
- 기사 카드의 순서가 웹진메인에 보이는 순서다
- 날짜는 `datetime`에 `YYYY-MM-DD`로 적는다 (웹진메인이 날짜순 정렬에 쓴다)
- 웹진 이름은 `site.json`에만 적는다: `{"team": "teamN", "name": "웹진 이름"}`

- 히어로가 영상이면 `<video data-excerpt="image" poster="./images/이름-hero-16x9.jpg">`처럼 영상에 표시를 붙인다. 웹진메인은 영상 대신 포스터 사진을 가져간다
- 같은 기사가 대표 기사와 기사 카드에 모두 있으면 웹진메인은 한 번만 보여준다 (주소로 구분)

## 8. 이미지 규칙

### 파일 이름
- 영문 소문자, 숫자, 하이픈만 쓴다. 끝에 비율을 붙인다: `주제-용도-비율.jpg`
- 예: `jeongbang-hero-16x9.jpg`, `jeongbang-hero-4x5.jpg`, `jeongbang-og.jpg`, `jeongbang-story-16x9.jpg`
- 같은 장면을 비율별로 잘라 두면 이름 앞부분은 같게, 비율만 다르게 붙인다

### 서브메인에 필요한 사진

| 파일 | 비율·크기 | 쓰는 곳 |
|---|---|---|
| `이름-hero-16x9.jpg` | 16:9, 최대 1600×900 | 히어로(PC), 웹진메인 카드 |
| `이름-hero-4x5.jpg` | 4:5, 최대 1080×1350 | 히어로(모바일) |
| `이름-og.jpg` | 1200×630 | 공유 미리보기 |
| 기사마다 대표 사진 `기사id-16x9.jpg` | 16:9, 최대 1600×900 | 대표 기사, 기사 카드 (상세페이지 대표 사진과 같은 파일) |
| `이름-video-16x9.jpg` (영상 섹션을 쓸 때) | 16:9, 최대 1600×900 | YouTube 썸네일 자리 |

### 크기와 용량 (실제 사진으로 확인한 기준)

| 용도 | 비율 | 최대 크기 | 원본 최소 가로 | 용량 |
|---|---|---|---|---|
| 서브메인 히어로 (PC) | 16:9 | 1600×900 | 1200px | 500KB 이하 |
| 서브메인 히어로 (모바일) | 4:5 | 1080×1350 | 600px | 500KB 이하 |
| 공유 미리보기 | 1200×630 | 1200×630 | 1200px | 300KB 이하 |
| 기사 대표·본문 사진 | 16:9 | 1600×900 | 500px | 300KB 이하 |
| 세로 사진·카드 | 4:5 | 1080×1350 | 300px | 300KB 이하 |
| 풀페이지 장면 | 9:16 | 1080×1920 | 720px | 300KB 이하 |
| 썸네일 (관련 기사 등) | 16:9 | 800×450 | 300px | 150KB 이하 |

- '원본 최소 가로'는 화면에 실제로 보이는 폭에서 정했다: 히어로 PC 1200px, 본문 사진 620px, 카드·사진 두 장 나란히 약 300px
- **원본보다 크게 늘리지 않는다.** 원본이 최대 크기보다 작으면 원본 크기 그대로 저장한다
- 원본이 '원본 최소 가로'보다 작은 사진은 그 용도에 쓰지 않는다. 더 작은 자리(카드, 썸네일)에 쓰거나 다른 사진을 구한다
- 형식은 JPG. 원본은 `콘텐츠/폴더/사진/`에 둔다 (`public/` 밖이라 배포되지 않는다)

### 사진 자르기
Claude Code가 `규칙/사진정리.md`대로 `tools/photo.py`로 자른다. 학생은 원본을 폴더에 넣기만 한다. 도구가 크기 · 용량을 맞추고, 늘리지 않고, `credits.txt`에 출처를 적는다.

### 쓰면 안 되는 사진
- 다른 사람의 워터마크(©, 블로그·업체 이름)가 있는 사진. 워터마크를 잘라내거나 지워서 쓰지 않는다. 사용 허락을 받았다면 표시를 남긴 채 출처를 적는다
- 출처를 모르는 사진, 검색 결과에서 내려받은 사진, 다른 웹진·블로그·SNS의 사진
- 직접 찍은 사진에 휴대폰이 넣은 날짜 · 문구는 자를 때 남길 부분 밖으로 뺀다. 뺄 수 없으면 그 자리에 쓰지 않는다

### 자르기
- 히어로는 아래쪽에 제목·CTA가 올라가므로, 주인공(폭포, 사람, 건물)을 위쪽 3분의 2 안에 둔다
- 4:5 모바일 히어로는 16:9를 늘리지 말고 원본에서 따로 자른다
- 가로 사진에서 4:5를 자르면 폭이 줄어든다 (1200×800 원본 → 640×800). 모바일 히어로 최소 600px을 넘는지 확인한다

### 사진 출처와 라이선스
- **직접 찍은 사진을 먼저 쓴다.** 사람이 나오면 초상권 동의를 확인한다
- 직접 찍은 사진이 아니면 **사용 허락이 분명한 사진만** 쓴다. 예: 공공누리 제1유형처럼 출처만 밝히면 쓸 수 있는 공공기관 사진. 라이선스 조건(출처 표시, 변경 가능 여부, 상업적 이용 가능 여부)을 확인하고 지킨다
- 검색 결과에서 내려받은 사진, 다른 웹진·블로그·SNS의 사진은 쓰지 않는다
- 직접 찍지 않은 사진은 캡션 끝에 출처를 적는다 (예: `사진: 한국관광공사`)
- 모든 사진의 출처를 `images/credits.txt`에 한 줄씩 기록한다

```
파일 이름 | 출처 | 라이선스 | 원본 주소
jeongbang-hero-16x9.jpg | 직접 촬영(team1) | - | -
jeongbang-falls-16x9.jpg | 한국관광공사 | 공공누리 제1유형 | https://...
```

## 9. 영상 규칙

**기준 한 줄: 소리 있는 영상은 YouTube, 짧은 무음 배경 영상과 배경음악은 저장소.**

| 구분 | 배경 영상 | 보는 영상 | 배경음악 |
|---|---|---|---|
| 예 | 히어로 배경, 풀페이지 장면, 영상 카드, 리스트·코스 항목 | 인터뷰, 브이로그, 코스 소개 | 풀페이지형·매거진 커버형의 분위기 음악 |
| 올리는 곳 | 저장소 `public/media/` | YouTube | 저장소 `public/media/` |
| 형식 | MP4(H.264), 720p, 15초 이내, **무음**, 파일당 8MB 이하 (서브메인 히어로는 5MB 이하) | YouTube 영상 ID | MP3, 128kbps, 파일당 3MB 이하 |
| 재생 | 자동 재생·반복·무음 | 누르면 재생 | **누르면 재생. 자동 재생 금지** |
| 첫 화면 | 포스터 사진 먼저 (`poster`) | 썸네일 + 재생 버튼만 먼저, 누르면 플레이어를 불러온다 | 소리 켜기 버튼만 보인다 |

### 배경 영상
- `<video src="./media/파일.mp4" poster="./images/포스터.jpg" autoplay muted loop playsinline preload="metadata">`
- 상대 경로로 넣는다. Cloudflare 작업 주소(파일당 25MB 한도)와 한경닷컴 서버 양쪽에서 똑같이 열린다
- 정지 버튼(44×44, 오른쪽 아래)을 둔다. 5초 넘게 움직이는 화면은 멈출 수 있어야 한다
- 사용자가 '움직임 줄이기'를 켠 경우(`prefers-reduced-motion`) 자동 재생하지 않고 포스터만 보여준다
- 영상에 소리 트랙이 있어도 무음으로만 쓴다. 음악이 필요하면 배경음악(MP3)을 따로 쓴다

### 보는 영상 (YouTube)
- 자막을 넣는다 (YouTube 자막 또는 영상에 입힌 자막)
- 처음에는 썸네일과 재생 버튼만 보여주고, 누르면 `youtube-nocookie.com` 플레이어를 불러온다. 페이지가 가벼워진다
- **서브메인 첫 화면에는 넣지 않는다.** 아래쪽 영상 섹션이나 상세페이지에 둔다. 광고로 들어온 사람이 YouTube로 빠져나가지 않게 하기 위해서다
- 세로 숏폼은 YouTube Shorts로 올리고 같은 방식으로 넣는다

### 배경음악
- 브라우저는 소리 있는 자동 재생을 막는다. **기본은 꺼짐**, 사용자가 "소리 켜기" 버튼을 눌렀을 때만 재생한다
- 소리 켜기·끄기 버튼(44×44, 화면 오른쪽 아래 고정, `aria-label` 필수)은 재생 중에도 항상 보이게 한다
- `<audio src="./media/파일.mp3" loop preload="none">`
- **서브메인(광고 랜딩)에는 넣지 않는다.** 상세페이지 중 풀페이지형·매거진 커버형에서만 선택해서 쓴다
- 웹 사용이 허용된 무료 음원만 쓴다. 출처와 라이선스를 `public/media/credits.txt`에 적는다

### 공통
- **세로 영상(9:16) 하나를 여러 곳에 같이 쓴다:** 서브메인 모바일 히어로(배경 영상) + Meta Reels 광고(광고 관리자에 직접 업로드) + YouTube Shorts. 광고와 첫 화면이 같은 장면이면 이탈이 줄어든다
- 사람이 나오는 영상은 초상권 동의에 영상이 포함됐는지 확인한다
- `영상/`에는 15초 이내 무음 mp4(8MB 이하)만 넣는다. 긴 영상 · 소리 있는 영상은 YouTube에 올리고 주소를 `영상/유튜브.txt`에 적는다
- 측정: YouTube 썸네일 클릭 `data-track="video_play"`, 배경음악 켜기 `data-track="bgm_on"`. YouTube 재생·완료는 GTM의 YouTube 동영상 트리거로 잡는다
